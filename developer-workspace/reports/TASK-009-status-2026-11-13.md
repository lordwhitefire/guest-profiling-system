## 4. Real defects found and fixed in this pass

1. **Directory pagination did not fetch.** The page state lived in the workspace component while the data hook kept its own page, so the current-page label changed but the table never re-fetched. Directory now uses the hook's page state; `Next page` issues `GET /api/guests?page=2&limit=20`.
2. **Directory order was not stable.** Added `ORDER BY created_at DESC, guest_id ASC` so pagination cannot repeat or skip rows.
3. **Duplicate/ambiguous row-action labels.** View/Edit and pagination arrows now carry `aria-label`, so the map and the click pass address the right control.
4. **Profile page crashed on a non-Date value.** `lastStayDate.toISOString` is gone; a safe `isoDay` formatter handles strings and invalid dates.
5. **Topbar Download Report was toast-only.** It now downloads `/api/export/directory`.
6. **Visit history read the empty `reservations` table.** It now derives visits from `guest_profile_links`; the period select filters by year.
7. **The standalone profile "Fill registration form" button was a disabled placeholder.** It now calls the same extension bridge and reports honestly when the extension is missing.
8. **Six stale duplicate profiles** from an earlier sync were soft-deleted; every active profile now has a link.
9. **The click-pass harness** was fixed for hydration timing, modal root selection, external `mailto:`/`tel:` links, sign-out verification, and guest selection on visit history. These are audit fixes, not product changes.

## 5. Remaining limits (not silently worked around)

1. **Extension load test is owner-dependent.** The unpacked extension must be loaded in Chrome. Until then, "Prepare Registration" and the standalone "Fill registration form" honestly report `Extension not detected`. The bridge, payload and acknowledgement path are implemented.
2. **Room, check-in and check-out cannot be persisted.** `ps_customer` has no such columns, and the task forbids a source-schema change. The fields stay in the registration form and are carried in the raw payload, but the hotel row stores only the QloApps columns.
3. **Six modal Save/Submit controls are not clicked in the audit** because they would create records. Their real API paths are covered by the two-hotel registration/user/tenant tests.
4. **Design-system demo buttons** are static by design and are counted as NOT RUN, not as product controls.
5. **Analytics "Last 30 days"** is a single-option select in the current build; it cannot change value.
