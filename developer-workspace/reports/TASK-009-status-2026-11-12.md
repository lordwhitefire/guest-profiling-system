## 3. External patch review — 2026-11-13 (not applied)

A proposed incremental patch was reviewed:

`/home/lordwhitefire/Downloads/TASK-009-incremental-2026-11-13.patch`

It applies cleanly (`git apply --check` exits 0), but it is **not shippable and was not
applied**.

Blockers found by inspection:

1. **Build fails.** Five new routes import `encrypt` / `decrypt` from
   `@gps/adapter-read/encryption`; that module only exports `encryptField` / `decryptField`,
   both of which require a `keyHex` argument. The core package also does not depend on
   `@gps/adapter-read` or `postgres`, so module resolution fails from `packages/core`.
2. **Hotel switching cannot work.** The migration seeds `tenant_memberships` for
   `admin@guestprofiling.com`. The actual local admin is `admin@grandvista.test`, so no
   membership rows are created and `/api/tenants/mine` returns empty.
3. **The seeded connection poisons sync.** Migration 002 inserts an empty read-only connection
   first. The sync and test routes select the oldest read-only connection, so the real
   connection added later is ignored and decryption of the empty seed fails.
4. **Only `guests_raw` is supported.** Registration and sync hardcode `guests_raw`. Grand
   Vista's source database has only `ps_customer`; no connection is configured for it. Two
   working registration forms are not delivered.
5. **Sync is not idempotent for contactless rows.** It creates a clean profile before checking
   whether the raw row is already linked. A row without phone or email creates a new orphan
   profile on every sync.
6. **The click-pass merge is corrupt.** `merge-retries.mjs` keys rows by
   `route::scope::label` with no control id or occurrence. Repeated `(icon)` row actions
   collapse into one key, so verdicts are applied to the wrong rows. Its “49 unmatched rows”
   is not trustworthy (the real unresolved count is 7), and its total is 249 instead of 251.
   The script also hardcodes `/tmp/gps-check`, so it does not run from the repo.
7. **The external status report overclaims.** It says tracker items 3, 4, 5, 6, 7, 9, 10, 11,
   12, 13 and 17 are closed. Live registration search is not implemented, the second messy
   source DB is not seeded, `Test Connection` is still not wired, and the sync/registration
   paths do not build.

Good parts worth keeping in a future implementation:

- the `guest_profile_links` design and derived visit count;
- the separate write connection for the registration form;
- the profile-page cookie-forwarding concept (but the `Host`-header-based URL needs a safer
  base URL);
- the manifest icon cleanup;
- no buttons removed.

Smaller issues also noted: the sidebar hotel badge still says “Grand Vista Hotel” after a
switch; “Save Defaults” sends `PUT {}` and is effectively a no-op; registration sends only the
check-in date and can be double-clicked into duplicate raw rows; the profile page forwarding
cookies to a `Host`-derived URL is an SSRF/cookie-leak risk.
